
# Contributing to Volphax Projects

We want to make contributing to Volphax projects as easy, transparent, and collaborative as possible.

We welcome contributions that improve the quality, reliability, accessibility, security, and usability of our technologies.

## Pull Requests

We actively welcome pull requests from authorized contributors.

1. Create a branch from `main`, or fork the repository when permitted.
2. Follow the project's coding standards and architectural guidelines.
3. If you've added or modified code that should be tested, add or update the corresponding tests.
4. If you've changed APIs, components, or public behavior, update the documentation.
5. Ensure that all tests, linting, type checking, and build checks pass.
6. Write clear commit messages following the Conventional Commits specification.
7. Submit your pull request with a clear description of the changes.

All contributions are subject to review by the project's maintainers before being merged.

## Development Standards

Volphax projects follow shared engineering principles:

- Write clean, maintainable, and well-documented code.
- Prioritize security, privacy, accessibility, and performance.
- Follow project-specific architecture and development conventions.
- Avoid unnecessary dependencies and complexity.
- Never commit credentials, secrets, or confidential information.
- Maintain compatibility with supported platforms and environments.

Individual repositories may provide additional development guidelines.

## Issues

We use GitHub Issues to track bugs, feature requests, improvements, and technical discussions.

When reporting an issue, please provide a clear description, relevant context, and sufficient instructions to reproduce the problem.

Before opening a new issue, check whether an existing issue already addresses the same topic.

Security vulnerabilities must be reported privately in accordance with our [Security Policy](SECURITY.md). Do not disclose security vulnerabilities through public issues or discussions.

## Code of Conduct

All contributors are expected to follow our [Code of Conduct](CODE_OF_CONDUCT.md).

We are committed to maintaining a respectful, inclusive, and professional environment across all Volphax projects and communities.

## Confidentiality

Contributions to private repositories are limited to authorized individuals.

Proprietary source code, internal documentation, credentials, and other confidential materials must not be disclosed or distributed without authorization from Volphax.

## Contributor License Agreements

Some Volphax projects may require contributors to accept a Contributor License Agreement ("CLA") or other contribution terms.

Where applicable, the requirements will be documented in the respective repository.

## License

Contributions to open source projects are subject to the license and contribution terms specified in the respective repository.

Contributions to proprietary projects are governed by the applicable agreements and intellectual property policies.

Access to a private repository does not grant permission to reproduce, redistribute, or disclose its contents.
